# fold_search harness — the operational contract, mechanically enforced

`scripts/fold_search.py` + `tests/test_fold_search.py` (21 tests). Stdlib only.
This is the spine the fold discipline ran on by hand for 267 ledger records;
now the machine refuses what agents used to have to remember to refuse.

## Known limits (labeled, with upgrade paths)

- **Memory cap is declared, not enforced** [GAP]: enforce by wiring the clone's
  `windows_job_memory.py` (Job-Object commit cap, triple-reviewed, 99% pass) as
  the runner wrapper. The seam is `runner.argv` — no harness change needed.
- **Promotion above `screened` is out of scope on purpose**: promotion requires
  matched seeds, uncertainty gates, and independent review (SKILL.md ladder);
  the harness stops at screened/killed/blocked so no code path can promote.
- **Billed-FLOP budgets are declared**: metering stays with FlopScope in the
  runner; the harness records what the runner reports.

## Usage

```bash
python scripts/fold_search.py predeclare spec.json --cells corpus/whestbench/cells --ledger corpus/whestbench/headroom/fold_ledger.json
python scripts/fold_search.py run corpus/whestbench/cells/<id>
python scripts/fold_search.py verdict corpus/whestbench/cells/<id> --ledger corpus/whestbench/headroom/fold_ledger.json
python scripts/fold_search.py audit corpus/whestbench/cells/<id>
```

Spec template: see the `HarnessBase.spec` dict in `tests/test_fold_search.py` —
it is the canonical example and is exercised end-to-end by the suite.

## Wave layer (`scripts/fold_waves.py`, 9 tests)

Cells gain optional `depends_on` (cell ids) and `writes` (paths). The scheduler:
topological waves (`plan`), cycle + unknown-dep refusal, same-wave write-overlap
refusal (the clone agent-graph's parallel-write guard), parallel execution with
strictly serialized ledger verdicts (`run-wave`), readiness that requires every
parent verdict to be `PASS_SCREEN` — a killed parent ends its downstream line —
and `export-graph`, which emits the live search DAG as graphify-compatible
node-link JSON (`type: search_cell`) for visualization beside the evidence
graph. The evidence graph stays canonical and deterministic; the cell DAG is
operational state, exported for navigation, never merged as evidence.
